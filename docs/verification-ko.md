# 한국어판 1차 검증 기록

확인일: 2026-10-20 (Asia/Seoul)

## 결과

- `npm run typecheck`: 통과.
- `npm run lint`: 오류 0개. 원본 `invitation-accept-card.tsx`의 내부 페이지 이동 방식 경고 1개가 남습니다.
- `npm test`: 328개 통과, 15개 건너뜀. PostgreSQL 통합 테스트와 별도 설정이 필요한 기존 테스트는 기본 환경에서 건너뜁니다.
- `npm run build`: Next.js 16.4.2 프로덕션 빌드 통과. `/`, `/playground`, 한국어 템플릿 3개를 포함해 정적 페이지 생성 완료.
- `npm audit --omit=dev`: 알려진 취약점 0개. 전체 감사에는 개발용 ESLint glob 의존성(`braces` 체인) 경고 5개가 남습니다. 이를 이유로 Next.js 14로 강제 다운그레이드하지 않았습니다.

## 브라우저에서 확인한 흐름

프로덕션 서버 `http://localhost:3000`에서 확인했습니다.

1. 한국어 첫 화면 → 체험 화면 진입.
2. `정보 주세요!` → 단어 일치 → 작성자 이름이 치환된 DM 미리보기.
3. `정보주세요` → 단어 일치에서는 불일치, 포함 일치에서는 일치.
4. 키워드가 비어 있으면 테스트 버튼 비활성화. 설정 변경 시 이전 결과 제거.
5. 상품 정보 템플릿 선택 → 키워드·DM·예시 댓글 자동 입력 → 상품 DM 미리보기.
6. 로그인 화면 기본 한국어 → 영어 전환 → 한국어로 복귀 → 새로고침 후 선택 유지.

체험 화면은 브라우저 로컬 판정만 수행합니다. 서버나 Instagram으로 테스트 댓글을 전송하지 않습니다.

## 의존성 변경

원본 lockfile에 알려진 취약 버전이 있어 호환 범위의 보안 업데이트를 반영하고 Next.js·Auth.js 최소 버전을 올렸습니다. Prisma CLI·Client·PostgreSQL 어댑터는 7.10.1로 맞췄습니다.

Auth.js의 Nodemailer peer 범위는 7/8 계열이나 해당 범위에 보안 경고가 남아 있어 직접 의존성과 override를 Nodemailer 10.1.7로 통일했습니다. 기존 createTransport/sendMail 사용부를 확인했고 한국어 메시지를 JSON transport로 생성하는 회귀 테스트를 추가했습니다. 실제 SMTP 서버로 이메일을 전송하는 검증은 포함하지 않습니다.

## 실제 발송 검증에 남은 항목

1차 검증 당시에는 Meta·메일 서비스 자격 증명이 없고 Docker 엔진이 실행되지 않았습니다. 이후 서버 준비 결과는 아래 별도 항목에 기록합니다.

한국어 설치 안내에 따라 PostgreSQL·Redis·메일·Meta를 설정한 뒤 일반 사용자 계정의 새 댓글 → Webhook 수신 → 작업 대기열 → DM 수신 → 발송 기록까지 확인해야 합니다. 앱 역할이 있는 계정의 테스트 성공만으로 일반 사용자 대상 권한이 준비되었다고 판단하지 않습니다.


## 팔로우 확인형 자료 공유 변경 (2026-10-20)

사용자가 제공한 예시의 댓글 → 첫 확인 DM → 미팔로우 재확인 → 팔로우 확인 후 링크 버튼 흐름을 반영했습니다.

- 자료 공유 템플릿에 첫 DM·확인 버튼·재확인 안내·🔗 링크 버튼을 기본 설정했습니다. 편집기에 같은 구성을 적용하는 버튼을 추가했습니다.
- 워커는 Meta와 Zernio 모두 명시적인 true 응답일 때만 팔로우 확인을 통과합니다. null은 재확인 안내로 처리합니다. 예전 reveal 버튼도 같은 확인을 거치며, 읽음 기반 자동 전달은 팔로우 필수 자동화에서 차단됩니다.
- 기존 팔로우 반영 지연 재조회(20초·40초)를 유지했습니다. 체험은 지연 없이 모의 결과를 보여주며 실제 Instagram 조회가 아닙니다.
- 로컬 테스트 332개 통과, DB 테스트 15개는 CI에서 실행합니다. 프로덕션 빌드와 수정한 파일의 린트가 통과했습니다.
- 브라우저에서 미팔로우·조회 실패 상태에서는 링크 버튼이 없고, 팔로우 완료 상태로 바꿔 재확인 버튼을 누른 후에만 링크가 표시되는 것을 확인했습니다.

이 검증에는 실제 Instagram 계정 연결이나 실제 팔로우 API 응답·DM 수신이 포함되지 않습니다.

## 실제 계정 연결을 위한 서버 준비 (2026-10-20)

- PostgreSQL 16·Redis 7을 실행하고 운영 준비용 DB에 마이그레이션 23개를 적용했습니다. 별도 테스트 DB에서 전체 테스트 349개가 통과했습니다.
- PC 내부에서만 접근 가능한 Mailpit SMTP로 로그인 링크 생성·수신·일회용 링크 로그인·워크스페이스 생성을 브라우저에서 확인했습니다. 외부 이메일 서비스 전송을 검증한 것은 아닙니다.
- 웹앱과 별도 DM 워커를 실행하고 임시 HTTPS 터널을 통해 `/api/health`의 DB·Redis·대기열·워커 정상 상태를 확인했습니다.
- 공개 HTTPS Webhook에서 올바른 인증 토큰의 challenge는 200·본문 일치, 잘못된 토큰은 403, 서명 없는 POST는 401임을 확인했습니다. Meta가 실제로 보낸 이벤트는 아직 받지 않았습니다.
- Meta 공식 필드 문서에 따라 계정 연결 시 `messaging_postbacks`·`messaging_seen` 구독을 추가했습니다. 기존 `comments`·`messages`만으로는 확인 버튼 클릭 이벤트 구독이 빠집니다. 요청 계약과 권한 오류 전파 테스트 2개를 추가했습니다.
- 프로덕션 빌드 통과, 린트 오류 0개·기존 경고 1개입니다.

실제 연결 버튼은 `INSTAGRAM_APP_ID`·`INSTAGRAM_APP_SECRET` 미설정을 정확히 안내했습니다. Meta 개발자용 Facebook 로그인이 필요하며 Instagram 연결 계정은 아직 0개, 실제 DM 발송은 0건입니다. 계정·대상 게시물·키워드·자료 링크와 Meta 앱 설정을 완료한 후 실제 댓글과 팔로우 상태로 검증해야 합니다. 임시 터널 주소는 재실행 시 바뀌며 상시 운영 환경으로 간주하지 않습니다.
